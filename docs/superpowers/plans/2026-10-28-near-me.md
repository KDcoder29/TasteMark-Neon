# Near me Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Places and Want to try entries get exact lat/lng (GPS, Maps link, or pin), and a "Near me" view lists and maps the current space's places by distance.

**Architecture:**
- Pure, tested modules hold the logic:
  - `geo.js`: distance, formatting, link parsing, nearby filtering;
  - `geocode.js`: Photon search;
  - `locate.js`: wraps the browser Geolocation API.
- Leaflet is lazy-loaded inside one wrapper component, `LeafletMap.jsx`. Three UI pieces use it: `LocationField` (forms), `NearMe` (view) and `FixLocations` (review sheet).
- A tiny Vercel function resolves short Google links. New DB columns come with a "save without them" fallback.

**Tech Stack:** React 19, Vite 8, Vitest, Leaflet 1.9.4, OpenStreetMap tiles, Photon geocoder, Vercel functions, Neon Postgres.

**Spec:** `docs/superpowers/specs/2026-10-28-near-me-design.md`

## Global Constraints

- Totally free: no API keys or billing. The only services are tiles from `https://tile.openstreetmap.org/{z}/{x}/{y}.png` and search from `https://photon.komoot.io/api/`.
- OSM attribution `© OpenStreetMap` is visible on every map.
- Location permission is requested only when Near me opens or "I'm here" is tapped. The user's position is never stored.
- Leaflet loads only through a dynamic `import('leaflet')`.
- GPS accuracy threshold is 50 m, GPS timeout 15 s, default radius 5 km, radius chips 1 / 3 / 5 / 10 km, search debounce 400 ms.
- `loc_source` is one of `gps`, `link`, `pin`.
- Directions URL: `https://www.google.com/maps/dir/?api=1&destination=<lat>,<lng>`.
- Git: Claude does not commit (project rule). Each task ends with tests green, and the user commits.
- Never pair `foo.js` with `Foo.jsx` (Windows case clash). Hence the names `geo.js`, `geocode.js`, `locate.js` with `LocationField.jsx`, `NearMe.jsx`, `FixLocations.jsx`, `LeafletMap.jsx`.

## Review Focus

1. **A Maps link with only a place ID** (`?cid=` or `/place/Name/data=!4m…` without `!3d`) must not produce coordinates: it returns null, and the form says so. Test in Task 1.
2. **A wrong link pair:** `@lat,lng` is the map centre, not the place. When both `!3d!4d` and `@` exist, `!3d!4d` wins. Test in Task 1.
3. **Places with no coordinates, or with only one of lat/lng**, are skipped by `nearby`, never treated as 0,0. Test in Task 1.
4. **The resolver as an open proxy:** a non-Google host, or a redirect to a non-Google host, is refused. Test in Task 3.
5. **API not migrated yet:** saving still works without lat/lng and warns once. Test in Task 2.

### Task 1: Geo core (`src/geo.js`)

**Files:** Create `src/geo.js` and `src/geo.test.js`.

**Interfaces (produces):**
- `hasCoords(p) -> boolean`: both `p.lat` and `p.lng` are finite numbers and in range.
- `distanceKm(a: {lat,lng}, b: {lat,lng}) -> number`: haversine with R = 6371.
- `formatDistance(km) -> string`: under 1 km gives `"850 m"`, rounded to 10 m; under 10 km gives `"3.2 km"`; otherwise `"12 km"`.
- `coordsFromMapsUrl(url) -> {lat,lng} | null`. Checks, in order: `!3d<lat>!4d<lng>`, then `q=`/`query=`/`ll=`/`destination=`/`daddr=` holding `lat,lng`, then `/place/<lat>,<lng>` or `/search/<lat>,<lng>`, then `@lat,lng`.
- `isShortMapsLink(url) -> boolean`: host `maps.app.goo.gl`, or `goo.gl` with a `/maps` path.
- `nearby(items, me: {lat,lng}, radiusKm) -> items with .km, sorted ascending`. It skips anything where `!hasCoords`.
- `directionsUrl(p) -> string | null`.

- [ ] **Step 1:** Write the failing tests:
  - `distanceKm` Vadodara (22.3072, 73.1812) → Ahmedabad (23.0225, 72.5714) is between 99 and 101.
  - `formatDistance(0.8523) === '850 m'`, `formatDistance(3.24) === '3.2 km'`, `formatDistance(12.6) === '13 km'`.
  - The URL `https://www.google.com/maps/place/Mandap/@22.31,73.17,17z/data=!3m1!4b1!4m6!3m5!1s0x0:0x1!8m2!3d22.3105!4d73.1702` gives `{lat:22.3105,lng:73.1702}`.
  - `q=22.3,73.18`, `query=22.3%2C73.18` and `@22.3,73.18,15z` each parse.
  - `https://maps.google.com/?cid=123` gives null.
  - `!3d95!4d10` (out of range) gives null.
  - `hasCoords({lat:0})` is false; `hasCoords({lat:'22',lng:'73'})` is false (strings are not numbers).
  - `nearby` drops items without coordinates, drops items beyond the radius, sorts nearest first and attaches `.km`.
  - `directionsUrl({lat:22.31,lng:73.17}) === 'https://www.google.com/maps/dir/?api=1&destination=22.31,73.17'`; `directionsUrl({})` is null.

### Task 4: Search and GPS helpers (`src/geocode.js`, `src/locate.js`)

**Files:** Create `src/geocode.js`, `src/geocode.test.js`, `src/locate.js` and `src/locate.test.js`.

**Interfaces (produces):**
- `photonUrl(q, bias?: {lat,lng}) -> string`: `https://photon.komoot.io/api/?q=<q>&limit=5&lang=en`, plus `&lat=&lon=` when a bias is given.
- `parsePhoton(json) -> [{ label, lat, lng }]`. The label is name, street, city and state joined with ", ", skipping empty parts and duplicates. GeoJSON order is [lng, lat].
- `searchPlaces(q, bias, fetchFn = fetch) -> Promise<[...]>`: an empty array for queries under 3 characters or on any error.
- `guessQuery(p) -> string`: name, area, city.
- `getPosition({ geo = navigator.geolocation, timeout = 15000 }) -> Promise<{lat,lng,acc}>`. It rejects with `Error` whose `code` is `'denied' | 'unavailable' | 'timeout' | 'unsupported'`.
- `GOOD_ACCURACY = 50`.

- [ ] **Step 1:** Write the failing tests:

  - `searchPlaces('ab')` resolves to `[]` without fetching.
  - A fetch that throws gives `[]`.
  - `getPosition` with a fake geo calling the error callback `{code:1}` rejects with `code 'denied'`; with no geo it rejects `'unsupported'`; success maps `coords.accuracy` to `acc`.
